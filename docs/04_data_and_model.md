# データとモデル

## データ

`generate_dummy_inquiries.py` から `dummy_inquiries.csv` を生成する。

|列|内容|
|---|---|
|`subject`|件名|
|`body`|本文|
|`label`|正解ラベル|

BERTの入力には `body` を使用する。

## 分類ラベル

|ID|ラベル|条件|
|---|---|---|
|0|希望配送日あり|日付・曜日のみ|
|1|希望配送時間帯あり|時間帯のみ|
|2|希望配送日時あり|日付・曜日と時間帯の両方|
|3|希望日時なし|日時指定なし|

## 学習と評価

日本語BERTを4クラス分類としてファインチューニングする。  
欠損・重複・ラベル数を確認し、学習用と検証用に分割する。Accuracy、Macro F1、混同行列で評価する。

## アプリ動作確認

保存済みBERTモデルをFastAPIで読み込み、Streamlitから分類を実行。

- 希望配送日あり
- 希望配送時間帯あり
- 希望配送日時あり
- 希望日時なし

各ラベルの代表文を入力し、分類ラベルと確信度が画面に表示されることを確認する。

## 返信下書きとヤマト運輸時間帯の動作確認（2026/9/4）

### 時間帯の正規化

APIは、配送時間帯を次のヤマト運輸の区分に正規化して返す。

|区分|APIの出力値|
|---|---|
|午前中|午前中|
|14:00-16:00|14:00-16:00|
|16:00-18:00|16:00-18:00|
|18:00-20:00|18:00-20:00|
|19:00-21:00|19:00-21:00|

全角・半角の数字・記号や「14時から16時」などの表記ゆれを正規化する。  
「午後」のようにいずれの区分か特定できない表現は、希望時間帯として自動確定せず `None` を返し、担当者が確認する。

### シナリオ評価

|入力文|期待する抽出値（日付 / 時間帯）|確認内容|
|---|---|---|
|9月8日の午前中に配送をお願いします。|9月8日 / 午前中|抽出値が返信下書きへ反映されることを確認|
|9月8日に受け取りたいです。|9月8日 / 指定なし|日付のみの返信下書きになることを確認|
|発送をお願いします。|指定なし / 指定なし|日時を確定しない返信下書きになることを確認|
|9月8日の14：00-16：00に配送をお願いします。|9月8日 / 14:00-16:00|全角コロンを含む入力を正規化し、返信下書きへ反映することを確認|

### 評価結果

日付・ヤマト運輸の時間帯の抽出値、および返信下書きへの反映を確認した。  
BERTの分類ラベルと確信度は補助情報であり、低確信度の場合は警告を表示する。担当者が本文・抽出結果・返信下書きを確認して修正する運用とする。
