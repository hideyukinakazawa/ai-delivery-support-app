# BERT学習計画

## 1. 学習の目的

Re:lationから取得した問い合わせの件名・本文をBERTで分類し、担当者による問い合わせ内容の確認を支援する。

本アプリのBERTは、返信や処理を自動で確定するものではない。
AIによる分類結果を画面へ表示し、担当者が内容を確認した上で対応することを目的とする。

チェックリストはBERTの分類結果で直接決定せず、発送前日・発送日・発送後2営業日という作業日に応じて表示する。

## 2. 分類対象

### 入力データ

* 問い合わせ件名
* 問い合わせ本文

件名と本文を結合したテキストを、BERTへの入力として利用する。

### 出力データ

問い合わせ内容に対応する分類ラベル。

分類ラベルの詳細は、`docs/06_bert_labels.md` を参照する。

| ラベルID | 分類名    |
| ----- | ------ |
| 0     | 配送日時変更 |
| 1     | 配送先変更  |
| 2     | 新品交換   |
| 3     | 同時回収   |
| 4     | 発送状況確認 |
| 5     | 修理状況確認 |
| 6     | キャンセル  |
| 7     | その他    |

## 3. MVPでの分類方針

MVPでは、1件の問い合わせに対して最も主要な分類ラベルを1つ付与する単一ラベル分類を行う。

1通のメールに複数の依頼が含まれる場合は、担当者が内容を確認することを前提とし、最も優先度が高い内容または主な依頼をラベルとして付与する。

将来的には、複数ラベル分類や重要度判定への拡張を検討する。

## 4. 学習データ

### データ作成方針

学習・動作確認には、抽象化・匿名化したデータを利用する。  
実際の送信済メールを社内環境で参照し、問い合わせの表現や分類観点のみを抽出する。  

### データの形式

CSV形式で、以下のような項目を用意する。

| 列名         | 内容          |
| ---------- | ----------- |
| inquiry_id | 問い合わせID |
| subject    | 件名      |
| body       | 本文      |
| label_id   | 分類ラベルID     |
| label_name | 分類名         |

例：

| inquiry_id | subject    | body            | label_id | label_name |
| ---------- | ---------- | --------------- | -------- | ---------- |
| dummy_001  | 配送日の変更について | 来週の配送日を変更したいです。 | 0        | 配送日時変更     |
| dummy_002  | 住所変更のお願い   | 配送先住所を変更してください。 | 1        | 配送先変更      |

## 5. データ件数の目安

最初の動作確認では、各ラベル30件以上のデータ作成を目標とする。

8分類のため、初期段階では合計240件以上を目安とする。
精度を改善する段階では、各ラベル50件以上へ段階的に増やす。

ラベルごとの件数に偏りがある場合は、少ないラベルのデータを優先して追加する。

## 6. 前処理

学習前に、以下の処理を検討する。

* 件名と本文を結合する
* 返信メールに含まれる過去メール本文を必要に応じて除外する
* 顧客名、注文番号などの個人情報・識別情報をダミー表現に置き換える
* 空白や改行を整形する
* 件名に付く `Re:` などを必要に応じて除去する

前処理の内容は、推論時にも学習時と同じ処理を行う。

## 7. 学習方法

日本語の事前学習済みBERTモデルをベースにし、作成した問い合わせデータを用いてファインチューニングを行う。

学習データは、分類ラベルの比率をできるだけ保ちながら、以下の3つに分割する。

| データ    |  割合 | 用途                   |
| ------ | --: | -------------------- |
| 訓練データ  | 70% | モデルの学習               |
| 検証データ  | 15% | 学習中の性能確認・ハイパーパラメータ調整 |
| テストデータ | 15% | 最終的な性能評価             |

## 8. 評価方法

以下の指標を用いて分類モデルを評価  

* Accuracy：全体として正しく分類できた割合
* Precision：ある分類だと予測したもののうち正解だった割合
* Recall：本来その分類である問い合わせを見つけられた割合
* F1-score：PrecisionとRecallのバランス
* 混同行列：どのラベル同士を誤分類しやすいかの確認

ラベルの件数に偏りが出る可能性があるため、全体Accuracyだけで判断せず、ラベルごとのF1-scoreとMacro F1-scoreを重視する。

初期目標は、テストデータでMacro F1-score 0.70以上を目安とする。
ただし、実運用では担当者が必ず内容を確認するため、数値だけでなく誤分類の内容も確認して改善する。

## 9. アプリでの利用方法

Re:lation APIから取得した件名・本文に対して、学習済みBERTモデルで推論を行う。

画面には以下を表示する。

* AI分類結果
* 分類ラベル名
* 分類の確信度
* 問い合わせの件名・本文
* 作業日に応じたチェックリスト

担当者はAI分類結果を参考に問い合わせ内容を確認し、必要に応じてチェックリストを更新する。

## 10. 改善の進め方

誤分類や「その他」に分類される問い合わせを確認し、以下の改善を行う。

* データ・学習データを追加する
* ラベルの定義を見直す
* 類似しているラベルを統合する
* 必要に応じて新しいラベルを追加する
* 前処理方法を改善する
* 学習条件を調整して再学習する

学習データ、モデルの設定、評価結果は、再現できるように記録
